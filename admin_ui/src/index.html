Trained models

Every completed job saves its weights as a new trained model, so training again (other data, steps or size) never replaces an earlier one. Click a model to open it: its files, a form to run inference on it, its training data audits and evals, and the past replies of the model. Audit asks the model the questions of its own fine-tuning dataset (each example is a case) and has the LLM judge, in batches, how close its answers are to the dataset's: a check that the training took, not a test of generalization.

    Datasets

    The datasets are the subdirectories of the server's training datasets directory that have a dataset.toml manifest; it names the dataset and its JSONL data file. You can also upload a JSONL file (one JSON object per line with instruction, output and optionally input): it becomes a dataset named like the file. A dataset is sent to the sidecar only when a job that uses it starts.

        Training data audit
        
        
        The model is asked the questions of its own training dataset and an LLM judges how closely its answers reproduce the dataset's, a batch of question/answer pairs per LLM call. Every case is something the model was trained on, so this checks that the training took (and, through the examples it fails, finds bad training data); it says nothing about how well the model generalizes.
        
        
        
        
        
        
        
        
        Evals
        
        
        The model is asked the questions of an eval and an LLM judges its answers against the expected ones, a batch of question/answer pairs per LLM call. Evals are for cases the model never saw; for now the server's eval still reads the model's training dataset (use the audit above for that).
